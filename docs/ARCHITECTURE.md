# Архитектура

`ui.py` — девять разделов Qt, выбор проектов/пар, фоновая работа через QThreadPool. UI не получает SQL-соединения фоновых задач. `google_source.py` — официальный Sheets API и read-only OAuth с токенами в keyring. `excel.py` — чтение и внутренние копии. `domain.py` — нормализация, отпечатки, статусы и сравнение. `service.py` — операции проекта, импорт, проверка и подтверждение. `history.py` — единое правило порядка и выбора отправки для сводки и экспорта. `export.py` — согласованный локальный снимок и атомарная запись XLSX. `storage.py` — схема SQLite и транзакции.

Внутри сервиса чтение Google и сохранение снимка выполняются в одной пользовательской операции, но сеть находится вне SQLite-транзакции. Проверка — чистая функция над сохранёнными данными; её можно запустить отдельно без сети. Подтверждение и экспорт — отдельные операции.

## Данные

- `projects`: проекты пользователя.
- `pairs`: до трёх слотов на проект; JSON-настройки включают снимок Excel, относительный путь его копии, схему, экспорт и таймер.
- `submissions`: ID источника, версия, УИК, исходное время, позиция строки, оригинальный payload, отпечаток, результат проверки, подтверждение, признаки актуальной версии и наличия в источнике.
- `operations`: начало, завершение и состояние чтения. `running` после перезапуска становится `interrupted`.
- `events`: история действий, включая прежние подтверждения и причины их снятия.

Модель версии: `(pair_id, source_key, revision)`. Частичный уникальный индекс гарантирует одну актуальную версию на ID. SHA256 строится по всем именованным значениям отправки после удаления только внешних пробелов. Изменение исходных пробелов сохраняет новую сырую версию с прежним подтверждением; смысловое изменение создаёт версию без подтверждения. Старые подтверждения остаются историческими и не участвуют в экспорте.

SQLite работает с WAL, `synchronous=FULL`, foreign keys и ограниченными по времени соединениями. Новый снимок, его проверки, снятие подтверждений, настройки и завершение операции фиксируются одной транзакцией. Ошибка чтения хранится отдельно и не заменяет успешный снимок. Внутренняя копия Excel создаётся до записи её пути в БД. При аварии до транзакции может остаться неиспользуемая копия; ранее используемые файлы не удаляются.

QLockFile исключает два экземпляра для одной рабочей папки. Блокировки по парам исключают конкурирующие операции внутри приложения. Новая операция чтения блокированной пары отклоняется.

## Принятые решения

- По ответу пользователя вручную разрешено подтверждать расхождения и отсутствие Excel. Неприменимая схема требует исправления.
- По ответу пользователя в Google есть ID и время: выбор этих столбцов обязателен. Дата чтения не используется для сортировки отправок.
- Один XLSX, отдельный лист на пару. Значение общего поля берётся из подтверждённой отправки Google. Уникальные поля Excel включаются по выбору.
- При одинаковом времени выбор последней записи блокируется до явного разрешения порядка строк.
- Неоднозначные повторные строки Excel не выбираются автоматически.
- Идентичность источника/ID/УИК нельзя менять поверх истории: новый источник подключается в новом проекте.
- Удаление строки Google не удаляет локальную историю. Использование исчезнувшей подтверждённой записи сопровождается предупреждением.

Программа не рассчитывает дополнительные контрольные соотношения и не изменяет Google Таблицы или исходный Excel.
